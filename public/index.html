支付数据接入

目标：不改现有支付系统，不让 AI 直接操作生产库。技术只需要提供一个安全的只读数据源。
推荐 · 工作量最低

① 只读副库 / 报表库

只允许 SELECT；最好不是生产主库；可限制 IP 和指定表。
已有就用

② 现有查询 API

如果系统已经有交易、商户、代理、分润查询接口，直接给文档和只读 Token。
最保守

③ Excel / CSV

第一版也可以每天导出 4～5 张表，先把指标和老板驾驶舱跑起来。

技术只需要给这些

1
交易数据
交易时间、金额、商户ID、交易状态、手续费/服务费（如果有）
2
商户数据
商户ID、商户名称、代理ID、状态、最近交易时间
3
代理数据
代理ID、代理名称、上级代理（如果有）
4
分润数据
代理ID、分润金额、对应交易/结算日期；或者告诉我们分润计算规则
5
成本 / 费率
通道成本、成本费率、商户费率；如果系统已有利润字段，直接提供即可
6
关联关系
商户、代理、交易、分润之间分别用哪个 ID 关联

第一阶段我们要算出来的结果

• 今日交易流水
• 今日手续费收入
• 今日通道成本
• 今日代理分润
• 今日公司利润
• 代理分润排行
• 商户交易下滑
• 今日 / 连续多日无交易商户

✓

✓
